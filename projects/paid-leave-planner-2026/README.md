# 有給休暇 連休最大化プランナー (paid-leave-planner-2026)

残りの有給休暇日数を入力するだけで、日本の祝日（2026年・2027年）と組み合わせて
**最も効率よく連休を作れる有給取得プラン**を自動で提案する、依存ライブラリなしの静的Webアプリ（MVP）。

## コンセプト

- **ターゲット**: 年に数回、有給休暇の使い道を計画する会社員・公務員
- **課題**: 既存の祝日カレンダーサイトは「祝日の一覧」を見せるだけで、「どの日に有給を使うと一番お得か」までは計算してくれない
- **差別化**: 「使う有給日数 → 実際に得られる連休日数」の**効率（倍率）**を全パターン算出し、指定した残り有給日数の範囲で貪欲法により最適な組み合わせを提示する
- **収益化仮説**（要検証・未実装）: 表示広告、または連休先の宿泊・旅行アフィリエイトリンクの掲載

## 起動方法（ローカル）

ビルド不要の静的サイトです。

```bash
cd projects/paid-leave-planner-2026
python3 -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

## テスト

```bash
cd projects/paid-leave-planner-2026
npm test   # Node.js 18+ 標準の node:test を使用（追加パッケージ不要）
```

`src/planner.js` のコアロジック（祝日カレンダー生成・連休ブリッジ検出・有給配分の貪欲法）を
`test/planner.test.js` でユニットテストしている。今回のサイクルでは以下の3ラウンドでデバッグを実施済み：

1. **1回目**: ユニットテスト作成・実行 → 全8件パス
2. **2回目**: Playwright (Chromium) で実ブラウザ描画を検証 → favicon 404 のコンソールエラーを検出
3. **3回目**: favicon を追加して再検証 → コンソールエラー0件、モバイル幅(375px)でも横スクロールなしを確認

## 既知の制約・未実装機能（QA記録）

- 2028年以降のデータは未収録（毎年、内閣府の官報公表後にデータ追加が必要）
- 春分の日・秋分の日は国立天文台の公表値を用いた集計であり、法的な確定日ではない旨をUI・READMEに明記済み
- 会社独自の休業日（夏季休暇・年末年始休暇など）には未対応。今後のスコープ候補
- 複数年をまたぐ連休（例: 12月末〜翌年1月上旬）の最適化は未対応（年単位で計算が閉じている）
- 広告・アフィリエイト機能は未実装（収益化は仮説段階）

## データ更新について

`src/holidays.js` のコメントに記載の通り、祝日データは内閣府の公表内容を元に集計した値。
年が変わるタイミングで内閣府サイト (https://www8.cao.go.jp/chosei/shukujitsu/gaiyou.html) の
最新情報と突き合わせて更新すること。
